# 领域文档

## 阅读规则

分析代码、编写规格或提出设计变更前，先阅读根目录的 `GLOSSARY.md`，再阅读 `docs/adr/` 下与当前工作有关的决策文档。

相关文件缺失时继续执行。领域术语或决策明确后，由领域建模流程按需补充文档。

## 文档布局

采用单上下文布局。

- `GLOSSARY.md` 保存项目领域术语。
- `docs/adr/` 保存架构决策记录。

## 术语使用

任务标题、重构提案、假设、测试名称等涉及领域概念时，使用词汇表定义的术语，并遵循其中的用词约定。

需要的概念尚未收录时，先判断该概念是否符合项目现有语言。确有缺口时，记录为后续领域建模事项。

## 决策冲突

提案与现有 ADR 冲突时，明确指出对应文档、冲突内容及重新讨论的理由，供用户判断。
